# 動作を軽くするための工夫と、さらなる改善案

## いまの状態

| 項目 | 実測・実測に基づく見積り |
|---|---|
| 全ファイル合計 | 約 250KB（アイコン込み。画像・音源ファイルはほぼ無し） |
| 外部ライブラリ | 0個 |
| ネットワーク通信 | 初回のみ。以降はオフライン |
| 敵の絵28体 | インラインSVG（追加のダウンロードなし） |
| 効果音9種 | Web Audioで合成（音源ファイル0個） |
| 文字認識のモデル | なし（フォントを描いてお手本にする方式） |

もともと軽い作りなので、通常の使用で問題が出ることは想定していません。
以下は「それでも重い」ときの手当てです。

---

## すでに入れてある工夫

### 保存の間引き

手書きの1画ごとに localStorage へ書くと、iPad で目に見えて重くなります。
`save-manager.js` は 400ms のあいだ変更をまとめて1回だけ書きます。

```js
const WRITE_DEBOUNCE_MS = 400;
```

### 手書きの点の取りこぼし防止と、描き直しの最小化

`getCoalescedEvents()` で間引かれた点も拾い、速く書いても線が角張りません。
再描画は書いている間だけで、待機中は何も描いていません。

### 認識のお手本のキャッシュ

文字ごとのお手本（特徴量）は一度作れば使い回します。
また、1問目の「こたえる」で待たされないよう、問題画面を開いた時点で
エンジンの準備を先に始めています。

### 画面を閉じるときの後始末

`ScreenRouter` は画面を切り替えるとき、必ず前の画面の `destroy()` を呼びます。
これがないと、遊ぶほどイベント購読とタイマーが積み上がって重くなります。

### 画面が見えていないときはアニメーションしない

`requestAnimationFrame` はタブが非表示だと呼ばれません。
経験値バーは `setTimeout` を使い、地図のズームは非表示時に一気に切り替えます。
（これを直す前は、アプリを背面にすると経験値バーが0%のまま固まっていました）

## それでも重いときの手当て

### 1. まず設定の「うごき → すくなめ」を試す

アニメーションをほぼ止めます。古い端末ではこれだけで体感が変わります。

### 2. 手書きの線を細くする

設定の「線の太さ → ほそい」。塗るピクセル数が減ります。

### 3. 地図のラベルを減らす

`src/map/map-renderer.js`

```js
const MIN_CELLS_FOR_LABEL = 3;   // → 6 にすると表示する県名が減る
```

### 4. 認識の解像度を下げる

`src/platform/recognition/stroke-recognizer.js`

```js
const SIZE = 64;   // → 48 にすると計算量がおよそ半分になる
```

精度は少し落ちますが、自信が下がれば自己確認に回るだけなので、
誤採点が増えるわけではありません。

### 5. お手本のフォントを1つにする

```js
const TEMPLATE_FONTS = [
  "'Hiragino Kaku Gothic ProN', …, sans-serif",
  // "'Hiragino Mincho ProN', …, serif",   ← コメントアウト
];
```

お手本づくりの時間が半分になります。ただし字形の許容範囲は狭くなります。

## さらに先の改善案（必要になったら）

### 認識の準備を Web Worker に逃がす

お手本づくり（約150文字ぶんの描画と特徴量計算）はメインスレッドで行っています。
いまのところ体感できるほど遅くはありませんが、
文字数の多い教材に広げるときは Worker に移すのがよいでしょう。
`recognizer.js` のインターフェースは非同期（`async`）なので、
呼び出し側を直さずに移せます。

### 地図をもっと粗くする

`src/content/pref-paths.js` は約55KBで、4300ほどの点でできています。
起動時の計算はありません（あらかじめ書き出してある）。
それでも重い端末では、`tools/build-map.mjs` の `SIMPLIFY_TOLERANCE` を
大きくして作り直すと、点が減って軽くなります。

### 図鑑カードの遅延表示

47枚のカードを一度に描いています。教材を都道府県より大きくする場合は、
`IntersectionObserver` で画面に入ったものだけ描くようにしてください。

### 学習記録の圧縮

`stats.studyDays` は直近365日ぶんに制限してあります。
数年使い続けても増え続けない設計ですが、
複数児童で1台を共有する機能を足す場合は、記録量の設計を見直してください。

---

## 測り方

ブラウザの開発者ツール → Performance で記録し、
「もんだい → こたえる → つぎへ」を数回繰り返します。

見るところ

- **Scripting が長い** → 認識の計算。`SIZE` かフォント数を減らす
- **Rendering / Painting が長い** → アニメーション。設定の「うごき」を減らす
- **メモリが増え続ける** → 画面の `destroy()` が呼ばれていない可能性

localStorage の使用量はコンソールで確認できます。

```js
JSON.stringify(localStorage).length   // だいたいのバイト数
```

47県ぶんの記録で 10KB 程度です（上限は通常5MB）。
